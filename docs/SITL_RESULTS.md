# PX4 SITL results

_Generated by `analysis/make_sitl_results.py` from `sitl/results/flights/`. Do not edit by hand._

**Simulated.** Every number here comes from PX4 v1.17.0 software-in-the-loop with PX4's own SIH physics model, flying the SIH quadrotor (airframe 10040, sihsim_quadx), driven over MAVLink by this repository's mission layer and trackers, with the gains tuned for this airframe in `config/tuned_gains_px4_sih.yaml`. No aircraft was flown.

Errors are against the simulator's ground truth from PX4's ULog (`vehicle_global_position_groundtruth`), over the mission phase only, using the same `tracking_metrics` as the reference comparison in [`RESULTS.md`](RESULTS.md). Each flight is one run in still air (SIH has no wind model), so these are single samples and not a statistical comparison.

The clock alignment residual is what is left after superimposing the position estimate the mission layer received over MAVLink on the one PX4 logged: MAVLink transport and sampling. It bounds how much of each error above could be an artefact of putting two clocks on one axis.

PX4 runs on the wall clock (the nolockstep build), so a host that stops scheduling it for long enough makes PX4 report a simulated sensor as timed out and its EKF degrades. A flight where PX4 logged that is a fault in the simulation rather than in anything under test, so the campaign re-flies it; the attempts column counts the flights and `attempts.json` beside each flight records why.
